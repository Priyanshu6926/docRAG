# DocTalk — RAG-Based Private Document Chat 📄💬

**DocTalk** is a privacy-focused Retrieval-Augmented Generation (RAG) web application that allows users to upload PDF documents and immediately engage in interactive Q&A in natural language. Every answer generated by the LLM is strictly anchored to retrieved document passages with explicit, clickable page-level citations.

---

## 🌟 Key Features

- **Page-Level Citations**: Answers explicitly cite the exact page numbers (`[Sources: Page 4, Page 7]`) used to construct the response.
- **Strict Context Boundary**: Built-in system prompt preventing the LLM from hallucinating or answering from outside knowledge ("I couldn't find that in this document").
- **Per-Document Vector Isolation**: Each document generates a dedicated ChromaDB collection (`doc_<id>`), ensuring zero cross-contamination between user files.
- **Zero Embedding Cost**: Uses local `sentence-transformers/all-MiniLM-L6-v2` embeddings for zero API inference cost.
- **Scanned PDF Safeguard**: Detects image-only / non-searchable scanned PDFs and provides clear error feedback.
- **Microservices Architecture**: Node.js/Express handling web user accounts, auth & chat persistence + Python FastAPI managing PDF parsing, vector search, and RAG execution.

## 🏗️ System Architecture

```
[React Frontend (Vite + Tailwind/CSS)]
         |
         | REST (JWT Auth)
         v
[Node.js / Express Backend] <-----> MongoDB (Users, Documents metadata, Chat history)
         |
         | Internal REST API
         v
[Python FastAPI RAG Service]
   ├── PyMuPDF (PDF Parsing with Page Tracking)
   ├── LangChain Text Splitter (500 tokens / 50 overlap)
   ├── SentenceTransformers (all-MiniLM-L6-v2)
   ├── ChromaDB Vector Store (Per-document Collections: doc_<id>)
   └── Gemini / Anthropic LLM (Strict Context Prompt & Citation Parser)
```

## 🚀 Getting Started

### Prerequisites

- Node.js (v18+)
- Python (v3.10+)
- MongoDB (running locally or MongoDB Atlas URI)
- Docker & Docker Compose (optional for full stack containerized run)

### Environment Setup

1. Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```

2. Set your Google Gemini API Key or Anthropic API Key in `.env`:
   ```env
   GEMINI_API_KEY=your_gemini_api_key_here
   ```

---

### Running via Docker Compose (Recommended)

Run the full stack (MongoDB, Python RAG Service, Node API, React Frontend) in one command:

```bash
docker-compose up --build
```

Access the application:
- **Frontend App**: `http://localhost:3000`
- **Node Backend API**: `http://localhost:5000`
- **Python RAG Service**: `http://localhost:8000/health`

---

### Running Services Locally for Development

#### 1. Python RAG Service (`backend-python/`)
```bash
cd backend-python
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

#### 2. Node.js Backend (`backend-node/`)
```bash
cd backend-node
npm install
npm run dev
```

#### 3. React Frontend (`frontend/`)
```bash
cd frontend
npm install
npm run dev
```

## 📡 API Endpoints

### Node.js Backend (`http://localhost:5000/api`)

- `POST /api/auth/signup` — User registration
- `POST /api/auth/login` — User authentication & JWT issuance
- `POST /api/documents/upload` — Upload PDF & trigger vector indexing
- `GET /api/documents` — Fetch logged-in user's documents
- `GET /api/documents/:id/status` — Document indexing status polling
- `DELETE /api/documents/:id` — Delete document, vector collection, and chat history
- `POST /api/chat/:documentId/message` — Send message, retrieve answer & citations
- `GET /api/chat/:documentId` — Fetch chat history for document

### Python RAG Service (`http://localhost:8000`)

- `POST /rag/ingest` — Parse PDF, split into chunks with page metadata, store vectors in ChromaDB
- `POST /rag/query` — Embed query, retrieve top-5 chunks, prompt LLM, parse source page citations
- `DELETE /rag/document/{id}` — Purge ChromaDB collection
- `GET /health` — Microservice health status

## 🧪 Test Verification & Edge Cases Handled

1. **Scanned / Non-Searchable PDFs**: Automatically detected if total text < 30 characters. Returns clear warning: *"This looks like a scanned or image-only PDF. OCR is not supported in v1."*
2. **Strict Citation Parsing**: Regex extraction of `[Sources: Page X, Page Y]` with fallback to retrieved vector metadata.
3. **Data Privacy**: ChromaDB collections named `doc_<documentId>` ensure vector spaces are partitioned per document.
